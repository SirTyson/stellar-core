## Meta-Patterns

1. **Tracy zones are not production overhead**: Self-time in zones guarded by `#[cfg(feature = "tracy")]` measures profiling instrumentation cost, not soroswap apply-path work. Always confirm that a profiled zone is present in non-Tracy production builds before treating its self-time as an optimization target.

2. **Protocol-visible `const_term` makes charge-count changes infeasible**: In the p26 soroban host, `ValSer` (cpu `const_term=230`, mem `const_term=242`) and `MemCpy` (cpu `const_term=42`) both accumulate as `iterations × const_term + inputs × lin_term`. Any reduction in the number of `charge()` calls directly and observably shifts `cpu_insns`/`mem_bytes`, which are verified by exact-budget tests in `budget_metering.rs` and `e2e_tests.rs`. Batch-construction or skip-serialization optimizations that change the call count are infeasible within a single protocol version.

3. **Aggregate zone time is an upper bound on removable work**: Cited profile self-time for a parent zone (e.g., `extend_current_contract_instance_and_code_ttl`, `invoke_host_function` wrapper, `read xdr with budget`) includes unavoidable first-call work, mandatory protocol-visible charges, and unrelated sub-operations. Must isolate the specific skippable subset via focused instrumentation and confirm it clears the 3% Medium floor before promotion.

4. **Store-local wasmi state cannot be pre-cached**: `wasmi::Linker::instantiate` produces an `InstancePre` that owns a store-allocated instance handle and resolved per-store `Func` objects. All of these are mutable and per-invocation; there is no immutable "instantiation prelude" that the current `soroban-wasmi` API exposes for safe caching across `Store<Host>` instances.

5. **Parallel apply setup is already pipelined with worker execution**: `applySorobanStageClustersInParallel` constructs each `ThreadParallelApplyLedgerState` immediately before launching that cluster's `std::async`. Later clusters' setup is already overlapped with earlier clusters' execution, so the pattern is not an all-setup-before-any-worker barrier. Most `applySorobanStageClustersInParallel` self-time is `std::future::get()` blocking waiting for the slowest worker, not serial construction.

6. **C++→Rust bridge: eliminating serialization still requires Rust decoding**: The soroban host requires native Rust XDR types (`HostFunction`, `AccountId`, `SorobanAuthorizationEntry`). Passing the original on-wire byte slice from the C++ side avoids re-serialization but does not eliminate the Rust `metered_from_xdr` decode or the corresponding `ValDeser` budget charges. "Eliminate the redundant roundtrip" hypotheses must account for the fact that only half the roundtrip (the C++ write) is removable.

7. **Frame-held `ScContractInstance` is a snapshot, not a live view**: `Frame::ContractVM { instance, .. }` and `Frame::StellarAssetContract(_, _, _, instance)` capture the instance at frame-push time. The executable field can be mutated by `update_current_contract_wasm` mid-frame. Any TTL-extension or dispatch optimization that reads the executable from the frame snapshot must explicitly handle this case; SAC-only variants may avoid the stale-executable bug but must still be measured against the current accepted storage fast paths.

8. **Engine lock-mode must be verified before contention claims**: The presence of a shared engine, a "locked during execution" comment, or shared ownership across parallel workers does not imply exclusive serialization. For `soroban-wasmi`, the hot instantiation path holds only a read guard (`RwLock::read`) on the engine's resources, permitting concurrent readers; the dominant work is mandatory per-store allocation of host Funcs, instance handles, memories, tables, and globals. Always check the actual lock mode and scope before inferring that sharding or per-cluster engine duplication would reduce worker wait time.

9. **Unwrap-mode `applyLedger` containment is mandatory before promotion**: Unfiltered Tracy totals for zones such as `scan`, `checkValidWithOptionallyChargedFee`, `verifySig`, or bucket lookups can be enormous (1–14 seconds) yet represent work almost entirely outside the measured `applyLedger` windows (TX-set construction, herder flooding, background scans). Always run unwrap-mode containment against the benchmark's `applyLedger` events and confirm the inside-apply fraction clears the Medium threshold before treating a large aggregate zone as an apply-path optimization target.

10. **SAC Storage Fusion Overhead Negates Lookup Savings**: Protocol-gated SAC balance read/write fusion (coalescing get+put storage accesses) passed tests but regressed soroswap in all three authoritative non-Tracy runs. Storage-access coalescing and changed cache access patterns can exceed the saved redundant lookup work for the soroswap SAC transfer pattern. Benchmark three authoritative non-Tracy runs before claiming that storage-access fusion reduces apply time.

11. **Auth Frame Push Is Mandatory for All Frames**: The authorization subsystem relies on every actual contract frame — including frames that do not directly mutate authorization state — to advance and later pop each tracker stack. Proposals to skip push_auth_frame or push_tracker_frame for "no-auth" SAC frames break invoker authorization that was pre-established on a calling frame. Any auth-frame optimization must preserve the tracker-stack invariant for all frames on the call stack.

12. **Native Wasm Frame Replacement Introduces New Native-Side Costs**: When replacing a Wasm contract frame with a native host emulation, the implementation must reproduce all mandatory outputs (return value, contract events, auth/TTL behavior) and typically introduces new metered costs absent from the original Wasm path: `metered_write_xdr` calls for pair-ID derivation, `sha256` hashing, `add_host_object` for return-value containers, event-topic/data construction, and `call_n_internal` machinery for retained subcalls. These new costs can match or exceed the savings from removing Wasm instantiation and dispatch. Always measure three authoritative non-Tracy benchmark runs before treating a native emulation as a net win.

13. **AMM Balance Reads Cannot Be Replaced by Reserve Arithmetic**: Soroswap reserves are cached pair state updated at the end of each swap; actual token balances are independent ledger state that can diverge through donations, issuer admin effects, or prior external state changes. Computing a post-transfer balance from reserve arithmetic (`reserve - amount_out`) is not behavior-preserving; only direct storage reads provide the actual post-operation balance. This divergence is intentional in the AMM design so that donated tokens are correctly folded into `amount_*_in`, K-invariant checking, emitted event fields, and updated reserves.

14. **Native Pool Micro-Optimizations Below ~10 µs/Swap Are Sub-Low After Normalization**: With ~7,000-8,000 swap calls per benchmark window and 8-way cluster parallelism, removable per-swap physical work contributes at most `per_swap_µs × swap_count / 8 / N_ledgers` to wall-clock apply time. At 10 µs/swap: ~10 µs × 7,900 / 8 / 71 = ~0.14 ms/ledger = ~0.06% of the 218 ms baseline. Individual µs-scale shortcuts within the native pool path (redundant storage probes, AddressObject construction, reserve batching) consistently produce sub-0.1% wall-clock savings. Combining several such shortcuts still remains below the 1% Low floor. Do not propose native-pool-path sub-optimizations unless they address a phase that is non-overlapping with the parallel workers or have direct non-Tracy measurement evidence of a larger impact.
