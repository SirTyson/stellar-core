## Meta-Patterns

1. **Parallel Thread State Setup Is Measured Noise**: Serial `ThreadParallelApplyLedgerState` construction before each async worker has been investigated three times (001-parallelize-thread-state-setup, 001-parallelize-thread-state-split, 002-parallel-cluster-setup-serialization). A full PoC was built and passed all tests but failed the benchmark gate with <0.5% average improvement. Do not re-propose parallelizing this specific path without a new measurement showing the setup cost is now dominant.

2. **Prefetch Redundancy Is a False Claim for Soroswap**: `prefetchTransactionData` and `prefetchTxSourceIds` do not overlap for Soroban-only ledgers. `prefetchTransactionData` builds an empty key set for soroswap-shaped transactions. Any hypothesis claiming redundancy in the prefetch path must trace the actual key sets before writing.

3. **wasmi `InstancePre` Is Not Reusable**: The pinned wasmi version's `InstancePre` is store-bound and one-shot. Any VM instantiation caching hypothesis must use the wasmi API correctly. Do not propose `InstancePre` caching.

4. **XDR Bridge Cost Is Distributed and Sub-Threshold**: C++/Rust XDR bridge preparation (`toCxxBuf`, `addReads`) for soroswap is a real but distributed cost that totals well below the 3% Medium floor. Caching encoded bytes in `InMemorySorobanState` or at TransactionFrame construction time have both been evaluated and rejected.

5. **SHA256 / TTL Key Budget Ceiling**: The entire in-apply SHA256 budget for soroswap is ~0.67% of apply time. Any hypothesis that only reduces SHA256/TTL-key recomputation is structurally below the 1% Low floor. Do not write SHA256-only hypotheses.

6. **Async With Immediate Join Is Neutral**: Moving work to `std::async` and immediately `get()`ing the future has zero wall-time benefit. Async offload only matters when the join is deferred past independent work on the original thread.
