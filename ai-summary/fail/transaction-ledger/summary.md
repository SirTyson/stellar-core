## Meta-Patterns

1. **Benchmark Warm-up Inflation**: `benchmarkModelTxTpsSingleLedger` includes `warmAccountCache()` before the timed sampling loop. Profiling during warm-up over-counts entry-scan and cache-miss costs that are not part of the steady-state apply window. Always isolate the timed region from setup calls.

2. **wasmi `InstancePre` Is Not Reusable**: Identical to the soroban subsystem finding — the pinned wasmi version's `InstancePre` is store-bound and one-shot. This has been verified at two subsystem levels.

3. **Prefetch Pass Overlap Is a False Claim**: For Soroban-only ledgers, `prefetchTransactionData` builds an empty key set. The two prefetch passes (`prefetchTxSourceIds`, `prefetchTransactionData`) do not overlap in the soroswap shape. Verified from two different hypothesis angles.

4. **Footprint Key Type Matters for InMemorySorobanState**: Classic trustline and account keys in the Soroban tx footprint bypass the `InMemorySorobanState` path entirely. Only CONTRACT_DATA and CONTRACT_CODE keys go through the in-memory Soroban state. Always filter footprint key counts by entry type before estimating call counts.

5. **Sub-Threshold Narrow Fixes**: Several transaction-ledger hypotheses (xdr_size skip, medida histogram disable, recordStorageChanges TTL precompute, CxxBuf precompute) project at 0.6–2.5% individually. These are all below the 3% Medium floor. A combined approach touching multiple of these paths might reach Medium, but each alone does not.
