# H002: Fused native router executor for the apply-load exact-token swap path

**Date**: 2026-05-24
**Subsystem**: transaction-ledger / soroban host native Soroswap path
**Severity**: High
**Impact**: Soroswap apply-time reduction by bypassing the remaining router Wasm frame and nested contract-call pipeline for the benchmark's canonical two-token swap
**Hypothesis by**: gpt-5.5, high

## Expected Behavior

For the specific Soroswap router invocation generated by `apply-load` (`swap_exact_tokens_for_tokens(amount_in, amount_out_min, [token_in, token_out], to, deadline)`), the apply path should produce the same ledger writes, authorization checks, events, return value, and contract errors as the Wasm router plus native pair/SAC calls. If all arguments and contract hashes match the audited benchmark shape, the host can execute the route as one protocol-gated native executor; otherwise it must fall back to the router Wasm unchanged.

## Mechanism

The current accepted stack has native pool getter/swap hooks, but every benchmark transaction still enters the router as a normal Wasm contract call through `call_contract_fn` and `Vm::invoke_function_raw` (`src/rust/soroban/p26/soroban-env-host/src/host/frame.rs:782-828`). The router frame then performs host calls for SAC input transfer, pool reserve getters, and pair swap, paying VM dispatch, nested frame push/pop, argument object conversion, and `call_n_internal` scaffolding around work whose shape is fixed by `src/simulation/ApplyLoad.cpp:3412-3477`. A hash-gated native router executor can parse the five router arguments, validate the two-token path, compute the pair address/selection using the same known pool instance entries, perform the input SAC transfer and native pair swap in one deterministic sequence, and return the same router result while avoiding the outer router VM frame and several nested contract-call boundaries.

## Trigger

Run the current soroswap apply-load benchmark from `ai-summary/CURRENT_STATE.md`. Each transaction invokes the router function `swap_exact_tokens_for_tokens` with a two-element path and source-account authorization; under the current tree this still reaches `Vm::invoke_function_raw` for the router even though the pair contract calls below it are already native-hooked.

## Evidence

The current trace still shows a large router/VM envelope inside the measured apply path. Timestamp-filtered against `applyTransactions`, `Host::invoke_function` contributes **8,244.655 ms total** over **7,851 events**, `Vm::invoke_function_raw` contributes **7,271.630 ms total** over **7,867 events**, and the Rust dispatch `call` zone contributes **5,134.323 ms total** over **23,569 events**. These are descendants of `applyLedger -> applyTransactions -> applyParallelPhase -> applySorobanStages -> applySorobanStageClustersInParallel`; they are not TX-set construction zones. With `NUM_CLUSTERS=8`, the VM envelope alone is roughly `7,272 ms / 8 = 909 ms` of critical-worker time over the **4,475.606 ms** traced applyLedger total, so even a partial fused-router removal has High-tier headroom.

This is not the earlier narrow "router trampoline only" idea that left all inner work mandatory. The current source now contains accepted native pool getter/swap code and direct SAC balance reads; a fused executor can use those primitives and additionally remove the router's input SAC transfer call boundary plus the pair-swap output SAC transfer boundary from H001. The deterministic order is explicit: input SAC transfer, reserve lookup, amount-out computation/checks, pair output transfer, balance reads, reserve update, event emission, return.

## Anti-Evidence

This is a larger consensus-critical native precompile and must be gated narrowly by protocol version, router Wasm hash, function symbol, argument shape, path length, known pair/pool instance layout, and benchmark-compatible error ordering. The router contract source/hashes must be audited; if the source is unavailable or the apply-load shape differs from production Soroswap, the executor should be rejected or limited to the benchmark-only hash. The PoC must show that budget/resource accounting changes are intentional and protocol-gated, and that fallback paths preserve all non-matching router calls.

### Trace Summary

The soroswap apply-load transaction does invoke the router Wasm with the fixed `swap_exact_tokens_for_tokens(amount_in, amount_out_min, [token_in, token_out], to, deadline)` shape, and `Host::call_contract_fn` currently reaches `Vm::invoke_function_raw` for that router before sub-calling token/pair work. The current tree also has hash-gated native pair getter/swap hooks below the router, so a router-level hook could technically be placed before `instantiate_vm`. However, the exact router bypass has already been reviewed as a native router trampoline on a native-pair baseline and rejected below the Medium threshold; the broader "fused" part is the previously rejected SAC-transfer fast lane, where preserving auth, rollback, diagnostics, storage, TTL, and event semantics keeps the expensive child-call-equivalent work.

### Why It Failed

This is not novel: the router portion is substantially the same as the recorded `002-native-router-trampoline-refined.md` failure, and the added attempt to fuse input/output SAC transfers is substantially the already rejected SAC-transfer fast-lane line of work. The hypothesis sizes impact from inclusive `Vm::invoke_function_raw`, `Host::invoke_function`, and broad `call` totals, but the router frame encloses mandatory child work: source-account SAC transfer auth and balance mutation, native pair swap validation, pair output SAC transfer, reserve reads/writes, event construction, diagnostics, and frame rollback behavior. A correct native executor must either keep child-frame-equivalent auth/rollback semantics or manually reproduce them; those are exactly the costs prior reviews found cannot be elided safely.

The fused mechanism also depends on implementing router contract semantics from opaque vendored Wasm bytes. `ApplyLoad.cpp` uploads `soroswap_router.wasm` through `include_bytes!`, and this tree does not contain audited router source or an equivalence harness for every error-ordering, budget, auth, and event edge case. Prior `002-codehash-native-soroswap-precompiles.md` already failed on this consensus-safety constraint. Given the objective's Medium floor, the remaining genuinely removable router VM/trampoline work is below threshold after cluster normalization, while the claimed larger savings require non-equivalent SAC/pair-call fusion.

### Lesson Learned

Inclusive router/VM spans are a poor proxy for removable router overhead once native pair hooks and typed SAC balance reads already exist. Future router hypotheses need a narrow measurement of router self-work only, audited router source/equivalence coverage, and a plan that preserves SAC/pair auth frames rather than counting mandatory child work as removable dispatch waste.
