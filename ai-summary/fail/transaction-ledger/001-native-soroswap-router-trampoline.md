# H001: Native Soroswap router trampoline for fixed two-token exact swaps

**Date**: 2026-05-22
**Subsystem**: transaction-ledger / Soroban host invocation
**Severity**: High
**Impact**: Soroswap apply-time reduction by bypassing one remaining router Wasm instantiation and router bytecode dispatch per swap
**Hypothesis by**: gpt-5.5, high

## Expected Behavior

For next-protocol apply-load soroswap swaps with the exact benchmark shape, `swap_exact_tokens_for_tokens(amount_in, amount_out_min, [token_in, token_out], to, deadline)` should preserve the same ledger effects, auth checks, frames, diagnostic behavior, events, and return value as the vendored router Wasm. The efficient path should recognize the router code hash, symbol, arity, two-token path, and instance layout, then perform the fixed router orchestration natively while falling back to Wasm for every non-matching call.

## Mechanism

After the accepted native pool-getter emulation, the current trace still reports `Vm::instantiate_wasmi - instantiate` at **828.5 ms** over **14,040** in-apply events. The soroswap swap shape builds one top-level router call per transaction, and that router call still enters `call_contract_fn`, constructs a fresh `Vm`, dispatches router Wasm, and then performs deterministic subcalls for a two-token path that is generated by `ApplyLoad::generateSoroswapSwaps`.

A next-protocol `try_call_native_soroswap_router_exact_swap` in `Host::call_contract_fn` could remove the router half of the remaining Wasm invocations and a large share of router-side host-import dispatch while preserving determinism by gating on exact code hash, symbol, argument shape, path length, and instance layout. This is structurally larger than VM micro-caches: it removes an entire fixed orchestration layer and leaves SAC transfer / pair swap execution on existing host-call paths unless those calls are separately proven safe to specialize.

## Trigger

Run the current soroswap apply-load benchmark (`soroswap, TX=2000, T=8`) from the baseline in `ai-summary/CURRENT_STATE.md`. Each generated transaction invokes the router contract's `swap_exact_tokens_for_tokens` with a two-element path, source-account auth, and the fixed footprint assembled in `ApplyLoad::generateSoroswapSwaps`.

- `src/simulation/ApplyLoad.cpp:3381-3505` — constructs the exact soroswap swap call shape, footprint, and source-account auth tree used by the benchmark.
- `src/rust/soroban/p26/soroban-env-host/src/host/frame.rs:768-814` — `Host::call_contract_fn` already gates the accepted native pool-getter path before `instantiate_vm`; this is the analogous insertion point for a router trampoline.
- `src/rust/soroban/p26/soroban-env-host/src/host/frame.rs:989-1103` — `instantiate_vm` still constructs a fresh wasmi store/instance for non-native Wasm calls, including router calls.
- `src/rust/soroban/p26/soroban-env-host/src/host/frame.rs:1124-1194` — `call_n_internal` performs external-call checks, diagnostics, reentry policy, and dispatch; the native router path must preserve these semantics.

## Evidence

- The accepted diagnostic trace in `CURRENT_STATE.md` still has `Vm::instantiate_wasmi` **14,040** times and `Vm::instantiate_wasmi - instantiate` **828.5 ms** after native pool getters removed the getter-only subset. The remaining count is consistent with roughly router + pair Wasm invocations per swap.
- Tracy self/total attribution for the same trace keeps `Vm::invoke_function_raw` and generated host-function `call` as dominant apply descendants, all under `applyLedger`, not TX-set construction.
- The existing native pool-getter success proves this codebase already accepts exact-code-hash, exact-symbol, next-protocol native emulation for the soroswap workload when frames, TTL behavior, and fallback paths are preserved.

## Anti-Evidence

- This is correctness-sensitive: without audited router source or an equivalence harness, native emulation of router orchestration can easily miss edge cases in deadline checks, path validation, amount-out-min errors, diagnostics, or sub-invocation ordering.
- The path must remain next-protocol-gated because it changes protocol-visible Wasm dispatch and metering. Released p26 execution must continue through Wasm.
- If the router's removable share is materially smaller than half of the remaining VM work, this may fall from High to Medium; PoC should add narrow Tracy spans around router-only native hits and remaining pair execution.

### Trace Summary

The generated benchmark transaction is a top-level `HostFunction::InvokeContract` targeting the Soroswap router's `swap_exact_tokens_for_tokens` with the exact two-token path and auth tree described in the hypothesis. The Rust host converts the external invoke to host values, runs `call_n_internal` external-call checks and diagnostics, then dispatches Wasm executables through `call_contract_fn`, which retrieves the contract instance, instantiates a VM from the executable hash, pushes a `Frame::ContractVM`, and invokes `vm.invoke_function_raw`. That is precisely the same class of code-hash-gated native Soroswap contract emulation previously investigated as `002-codehash-native-soroswap-precompiles.md`; this variant narrows the scope to the router, but the router half of that prior mechanism failed for the same correctness reason.

- `src/simulation/ApplyLoad.cpp:2855-2913` — uploads factory, pair, and router Wasm blobs from `rust_bridge::get_apply_load_soroswap_*_wasm`, computes their code hashes, and deploys them as normal Wasm contracts.

### Why It Failed

This hypothesis is not novel: it is the router-only subset of the previously failed code-hash native Soroswap precompile investigation. The prior record already rejected native router/pair precompiles because the contracts available to stellar-core are vendored Wasm blobs and there is no audited in-tree equivalence harness proving that native Rust/C++ orchestration preserves all consensus-visible behavior. The source trace confirms the proposed insertion point would bypass the same production Wasm dispatch and would need to reproduce router validation, auth/sub-invocation ordering, diagnostics, frame rollback, budget/metering, event behavior, and error surfaces exactly; narrowing from router+pair to router-only does not remove that blocker.

### Lesson Learned

Code-hash native emulation of Soroswap benchmark contracts should not be re-proposed unless the investigation first supplies audited exact contract source plus an equivalence harness for the targeted function. Shape-gating on the benchmark's fixed two-token path is not sufficient for consensus-critical host execution, even when the performance opportunity is real.
